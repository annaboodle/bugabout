# Bugabout project guide

Last reviewed: 2026-08-31

## Purpose

Bugabout turns a geocaching trackable history into an animated, shareable journey. The product name is **Bugabout** and the tagline is **Follow your bug about.**

The experience should feel like a small travel documentary rather than a conventional analytics dashboard: warm, playful, map-first, story-led, and easy to share.

## Current implementation

Bugabout is currently a zero-build static prototype:

- `index.html` contains the application structure and locally loaded assets.
- `styles.css` contains the full responsive visual system.
- `app.js` contains the normalized journey renderer, sample data, Leaflet setup, animation, statistics, interactions, and file-import UI.
- `kml-importer.js` converts an official Geocaching trackable KML export into Bugabout's normalized journey shape.
- `bumblebee.js` synthesises the opening figure of Flight of the Bumblebee with the Web Audio API.
- `livereload.js` is a development convenience: it polls the static server for changes to the authored files and reloads when one lands. It returns immediately on any non-local hostname, so it is inert in production, and there is no build step for it to hook into instead.
- `country-lookup.js` resolves a coordinate to a country from vendored boundaries, since KML carries no country field.
- `journey-link.js` encodes a journey into the URL fragment and reads one back, so a route can be shared without a backend.
- `vendor/countries.json` is the boundary index it loads, generated from `vendor/ne_50m_admin_0_countries.geojson` by `tools/build-countries.mjs`.
- `vendor/us-states.json` resolves a US stop to its state, generated by `tools/build-states.mjs`. `tools/lib/boundaries.mjs` holds the slimming both build scripts share.
- `fixtures/` contains real KML exports named only with their public `TB...` references for repeatable testing.
- `tests/smoke.html` and `tests/smoke.mjs` exercise the browser-only importer, boundary lookup, and journey-link modules against both fixtures. The page publishes a final `data-status`, which the headless runner reads directly instead of relying on an arbitrary sleep.
- `tools/run-smoke-tests.mjs` serves the project on an ephemeral local port and runs that suite in an installed Chromium-based browser without adding a package dependency.
- `vendor/leaflet.css` and `vendor/leaflet.js` pin Leaflet 1.9.4 locally.
- `README.md` describes local setup and the current milestone.

There is no backend, package manager, bundler, authentication layer, direct URL importer, or API integration. KML files are parsed locally in the browser and never uploaded by Bugabout.

The `tools/` scripts are one-time data preparation, not a build step. Run them only when a Natural Earth source is replaced; the committed `vendor/countries.json` and `vendor/us-states.json` are what ship. `tools/build-states.mjs` downloads its ~39 MB source to a cache outside the repo, because only the 51 US features are needed.

## Run and verify

The page reloads itself when a source file changes, so editing and checking needs no manual refresh. `livereload.js` polls `HEAD` on the authored files roughly once a second and reloads on a changed `Last-Modified`.

Start a local server from the project root:

```sh
python3 -m http.server 4173
```

Open `http://127.0.0.1:4173/`.

Minimum verification after meaningful changes:

1. Run `node tools/run-smoke-tests.mjs`. It covers both fixtures, KML parsing, country/state derivation, antimeridian data, and share-link round trips.
2. Run `node --check` on every changed JavaScript or MJS file.
3. Load the app with browser developer logs free of errors and warnings.
4. Import `fixtures/TBBDVQG.kml`; confirm 6 stops, a 1.7-mile final total, 1 country (United States), play/pause, scrubbing, and stop navigation.
5. Import `fixtures/TBA5TD9.kml`; confirm 2,472 stops, a 176,530-mile final total, 22 countries including Macao and Monaco, smooth playback, a virtualized 64-stop list window, and viewport-driven markers capped by `MARKER_BUDGET`.
6. Confirm imported countries explain their derived provenance in the readout tooltip and **How it works** dialog. Temporarily make `vendor/countries.json` unreachable and confirm the player falls back to `countries not in KML` with a clean console.
7. Test speed selection, the camera toggle, sharing, the **How it works** dialog, and KML selection and drag and drop.
8. Check at approximately 1280×720 and 390×844. Confirm the player remains visible and the page has no horizontal overflow.

## Trackable data safety

Geocaching trackables have a public reference beginning with `TB` and a separate private tracking code printed on the physical item.

- Accept, display, store, and share the public `TB...` reference only.
- Never include a private tracking code in source, fixtures, logs, URLs, screenshots, analytics, or error messages.
- Treat incoming `tracker=` query values as potentially private. Do not persist or repeat them.
- Do not imply that sample data belongs to a real trackable.
- The current sample route is fictional and must remain visibly labeled **Sample journey**. That pill is shown only for the sample: imports carry no status pill, because importing is the sole way to load a bug and a label saying so tells the user nothing.
- A production importer should use an approved Geocaching integration or an explicit user-provided KML/GPX export. Do not silently introduce page scraping.

As of 2026-08-28, Geocaching's official API is limited to approved Authorized Developers. Keep the official [API program](https://partnerships.geocaching.com/geocachingapi), [partner request form](https://partnerships.geocaching.com/apiapply), and [API License Agreement](https://partnerships.geocaching.com/api-license-agreement) as the production integration path, but do not block KML prototype progress on approval.

A URL-only importer cannot be implemented reliably in the current static frontend. Confirmed on 2026-08-28: the public trackable page is anonymously readable, but the official `/kml/tbkml.aspx?tbguid=...` endpoint returns an empty response without a signed-in Geocaching session, and Geocaching does not send cross-origin access headers that would let Bugabout read either resource from its own origin. A normal website also cannot read a file that another site downloaded without the user explicitly selecting or dropping it.

Do not work around this with server-side page parsing, authenticated scraping, shared cookies, or collected Geocaching credentials. The Groundspeak Terms of Use effective 2026-03-04 prohibit robots, spiders, scrapers, or other means of collecting service data without express written permission. Section 4.16 of the current API License Agreement likewise disallows acquiring Geocaching data through scraping or similar methods without express written consent, and section 4.22 requires each API user to authenticate through OAuth. The intended direct-import design is therefore: approved API client → user connects Geocaching via OAuth → public TB code resolves through the authorized API → normalized journey data. Confirm available trackable-history scopes and fields with Geocaching during enrollment.

## Product and interaction decisions

- The animated bug is the narrative focus; the route, current date, location, mileage, and story advance together.
- The default journey is the real `fixtures/TBA5TD9.kml`, not the fictional sample, so a first visit shows what an actual trackable's travels look like. The sample remains the offline fallback when that file cannot be fetched. The fixture therefore doubles as production content; do not delete or rename it as if it were test-only.
- Playback duration is `12s + 2.8s x sqrt(stops)`, capped at 150 seconds. It used to be linear with a 60-second cap, which every journey over about fifty stops hit, so a 50-stop and a 2,472-stop journey ran for exactly the same time and the large fixture raced past at 41 stops a second. Square root keeps short journeys brisk and gives long ones room to be watched.
- Play and speed sit together in `.player-transport`. Speed is a transport control, not a statistic, and the readout row beside it is only for numbers that climb as the bug travels.
- Camera zoom is quantised to whole levels (`CAMERA_ZOOM_STEP`). With fractional zoom one frame landed on 8.2 and the next on 8.4, which reads as a glitch rather than a move; whole levels also keep tiles on their native level instead of upscaling.
- The camera holds until the bug nears the edge of the **viewport**, not of the frame it was built from. Holding against the frame failed badly: once a frame went globe-scale it contained the whole journey, so the camera never re-framed, while at minimum zoom the viewport could not display that frame and the bug spent a third of the playback off screen.
- Because everything stays visible at a wide zoom, leaving the viewport is not enough on its own — the camera would zoom out for an ocean crossing and never come back. It also re-frames when the journey warrants a view at least `CAMERA_ZOOM_REGAIN` whole levels tighter, which recovers the close view without reacting to small differences.
- Measured on the large fixture: 41 view changes across a 150-second playback, a median of 3 seconds apart, 6 under a second, and the bug never off screen. The earlier build made 82 with 48 of them under a second.
- Count camera changes by the visible tiles, not the map-pane transform. A zoom change resets that transform to zero, so watching it alone silently undercounts.
- The camera control hides itself when the whole journey already fits at zoom `CAMERA_CONTROL_MIN_ZOOM` or closer, and the map simply stays fitted. On a journey inside one neighbourhood there is nothing to follow, and offering the choice invited the worse option.
- The camera's zoom is floored at the whole-route fit, so following can never show *less* than fitting. Without that floor a journey the camera window already spanned produced a follow frame of the whole route but with heavier padding and a floored zoom, so **Follow bug** came out strictly wider than **Whole route** — and, having nothing to re-frame for, never moved either.
- **Whole route** and **Follow bug** are two states of one camera, shown as a segmented control rather than two buttons. They were separate before, and Fit route cleared only `followActive`, so the next scrub silently re-engaged the camera and undid the fit. Choosing whole route now clears `followEnabled` and sticks until follow is chosen again; clicking the selected segment re-fits, since the map may have been panned.
- Extreme-value stats name the stop they came from, with the cache code linked and its region and country beside it. A bare "121.8° E" says nothing a reader can act on. Longest hop names both ends, since a distance between one named place and nowhere is not a distance.
- Comparison tiles carry a minimum mileage and disappear below it: the Moon needs 1% (2,389 miles), coast to coast one crossing (2,790), marathons five (131), and the times-around-the-world note a tenth of a lap (2,490). Without them a six-mile journey reported "0%", "0×" and "0 marathons".
- The countries, states and continents tiles open the same list dialog as the player readouts, but over the whole journey rather than progress so far, since the tiles are totals.
- The map camera holds a frame and only re-frames when the bug leaves it. Framing the next few stops instead meant chasing all 2,472 caches, which was exhausting to watch. It now takes the bounds of a `CAMERA_LOOKBEHIND`/`CAMERA_LOOKAHEAD` window, holds that frame until the bug crosses out of it (`CAMERA_FRAME_INSET`), then glides to the next. On the large fixture that is 43 re-frames across a 150-second playback, roughly one every 3.5 seconds, with the bug never leaving the screen. **Follow** in the map topbar toggles it; **Fit route**, dragging, wheel-zoom and double-click all disengage it.
- `CAMERA_STYLE` switches between `"cut"` (current) and `"glide"`. Cutting removes continuous motion altogether. Its cost is rhythm: re-framing arrives in bursts rather than at a steady rate, so on the large fixture 48 of 82 cuts land less than a second after the previous one, between holds as long as fifteen seconds.
- Padding the held frame to reduce cuts was tried and reverted at 0.35: the frames grew past what the minimum zoom can display, so the frame no longer fitted the viewport and the bug fell outside it. A small 0.08 slack remains.
- Widening the frame after a short hold was tried and reverted. It feeds back on itself: a frame too wide to fit at the minimum zoom leaves the bug outside it, which forces another re-frame, which widens again. It ran away to a whole-world view with the bug off screen half the time. Any future attempt at evening out the rhythm has to hold the *old* frame longer rather than enlarge the new one.
- Discrete jumps snap the camera, playback eases it. The camera only advances when progress does, so scrubbing to a distant stop and releasing would strand it part-way through a glide.
- Playback supports play/pause, timeline scrubbing, 1×/2×/4× speed, direct stop selection, and route fitting.
- The countries and states readouts open a list of the places reached so far, in first-visit order with a per-place cache count. They are buttons, not statistics: whatever the readout counts, the dialog must enumerate exactly.
- Journey log markers carry a pin, not the stop number. Four-digit numbers overflowed the circle, and the stop number already sits at the end of the row.
- Hovering a stop marker turns it the legend's green, which answers "what is this dot" against a trail that colours recent stops coral.
- Recently visited stops fade from coral back to green across `MARKER_TRAIL` stops, leaving a wake behind the bug. Recency is measured in stops, not seconds, so the trail survives pausing and scrubbing; only markers inside the window are touched, so the work stays bounded. A `--recency` custom property drives a `color-mix`, which means no per-marker class churn.
- The journey heading carries whole-journey totals under the description, distinct from the player's running counts: miles, countries, US states, continents and unique caches. Mileage leads because it is the number this community measures trackables by, and it carries the "times around the world" comparison that gives a six-figure figure meaning. Tiles reading zero are dropped, so a journey inside one country shows neither states nor a second continent.
- The player card is the single home for live journey state. Miles traveled and countries sit beside the timeline that drives them, because both readouts advance with playback. There is no sidebar statistics grid.
- Mapped-stop count and travel duration are deliberately absent: the player already says `Stop N of M`, and KML has no dates to measure duration from.
- The timeline is labeled Start / Latest, or three years when the journey has dates. "Halfway" was dropped: it marked the middle of the scrubber, not the middle of anything a reader navigates by, while the years are real data and stay.
- There is no map legend. The timeline track carries the route ramp and the playhead travels it, which explains the chronology without a chip floating over the map. The trade is that the ramp is only revealed as playback advances, so a first look at an unplayed journey has no colour key.
- The journey log has two groupings, switched by the **By time / By place** toggle. **By time** is the flat chronological list; **By place** is a country → state → caches tree. Both stay available because the log is the only place the ordered sequence can be read, while the map and timeline carry chronology on their own.
- Place rows show a flag, the name, and the count on the right. Do not add a per-row cache-count subtitle: it repeats the number already at the end of the row. The only inline detail is the state tally on the United States.
- The place tree groups by aggregate, not by visit. The large fixture crosses borders 66 times, so a row per visit would mean 67 country rows and 140 state rows including 36 single-stop blips; aggregating gives 22 and 19 clean rows. Countries and states are ordered by first visit, so the list reads as an itinerary and matches the route ramp's direction.
- Only one country and one state are open at a time. That accordion is what keeps a leaf list windowable, since Washington alone holds 1,519 caches.
- Opening a place moves playback to its first stop; closing one leaves the bug where it is. The open group tracks playback, so the highlighted country follows the bug across all 66 crossings.
- Desktop uses a scrolling story sidebar beside the map.
- Mobile orders the workspace title and description, then the map, then the journey log, so the reader knows whose bug they are watching before they watch it. The sidebar becomes `display: contents` at that width so its two halves can be placed around the map; its padding and paper texture move onto them, since a contents box has none of its own. The cost is that the map now starts about 510px down, leaving roughly 330px of it in the first viewport.
- Statistics shown during playback represent progress up to the current stop, not final totals.
- Share copies a link that actually replays the journey. `journey-link.js` packs the title, description, official mileage, cache codes and coordinates into the URL fragment, so nothing is stored and nothing reaches a server — the link is the data. The fragment is adopted into the address bar when shared, and cleared when a new KML is imported.
- Sharing has a hard ceiling of `MAX_URL_LENGTH` (2,000 characters), past which messaging apps, mail clients and QR codes mangle links. Over that, the button says the journey is too large rather than copying something broken. Roughly 450 stops fit; the description is dropped first, since it is the most expensive field and the route is the point.
- Shared links embed cache coordinates, which Geocaching withholds from signed-out users. This is a deliberate product decision, taken knowingly: the sharer downloaded the data legitimately and chooses to pass on their own bug's route. Do not widen it into bulk redistribution.
- **Open KML** and drag and drop are the only ways in, so **Open KML** is the primary action in the intro bar with **How it works** beside it. There is no TB-code or URL field: a static frontend cannot resolve a code into a journey, and a search box that only ever answers "go download a file" reads as a broken feature.
- The **How it works** dialog is the canonical import instructions, including that geocaching.com sign-in is required before **View in Google Earth** returns a usable file. Keep it accurate when the import path changes.
- Imported files are read locally with `File.text()` and are not sent to a server.
- Never fabricate missing KML fields. Date-less imports use `Stop N of M`, and travel duration displays as unavailable; visit dates, log text, cache titles, and photos are never invented.
- Absent fields are omitted, not narrated. The importer leaves kicker and story empty rather than printing a sentence about what the format lacks.
- The story card is the active row of the journey log, and the log window opens *on* the current stop rather than centring it. So the card sits at the top of the list with the next stop connected directly below it, and playback moves the journey underneath a card that stays put. A separate pinned element was tried and removed: it duplicated the stop that was already the first row.
- Log transitions are for user actions only, never for playback. Expanding a gap or switching grouping animates; the signature-driven rebuilds that happen as the bug moves must stay silent, or a journey advancing 16 stops a second would strobe. `rebuildLogWithTransition` is the only path that animates.
- Expanding earlier stops measures the active card's on-screen position and restores it after the rebuild, adjusting the sidebar's scroll on desktop or the window's on mobile. Without that anchor, inserting 64 rows above the card shoves it off screen and the reader loses their place.
- Gap rows in the log are buttons. While paused they pull another `LOG_WINDOW` of stops into view in either direction; starting playback or loading a journey resets the expansion, because the window's normal job is to follow the bug.
- The selected row *is* the card: `.stop-item.active` carries the warm treatment, the larger serif code, the location, the cache-link arrow, and the kicker and story text when the journey has any. Every row renders its story markup hidden, so revealing it is the class toggle that already runs and playback still never rebuilds the list. Do not reintroduce a card that has to be moved between rows.
- In **By place** mode a collapsed country has no row to style, so the selected stop shows only as a highlighted place row. The player carries the current stop in both modes.
- A trackable description clips to five lines behind **Read more**. The full text is always in the DOM and clipped by height, so opening it is an animatable transition rather than a text swap. Whether the toggle appears is measured from actual overflow, not guessed from a character count, and the clip height must be expressed in the paragraph's own font metrics — `em` on the wrapper resolves against its inherited size, which silently made "five lines" six and a quarter.
- The readout row holds equal columns with a reserved width. Sized to content, it resized on every mileage digit and shunted the countries and states readouts sideways as the bug travelled.
- On mobile the speed control stacks under the play button, which narrows the transport cluster from 96px to 46px and gives the location line the room it needs.
- State is derived the same way, for US stops only. The states readout appears only when a journey actually enters the United States, and counts distinct US admin-1 units — a journey through Île-de-France and Attica has regions but no states.
- `region` holds the admin-1 name alone and must never bake in the country; the story card composes `region, country` itself. The sample data was rewritten to follow this.
- Country is the one exception, and only because it is derived rather than guessed: `country-lookup.js` resolves it geometrically from the stop's own coordinates. It must never overwrite a country that arrived with the journey, and if the boundary data cannot load the statistic falls back to the unavailable state rather than showing a number.
- Provenance for that derivation lives in the countries readout's tooltip and in the **How it works** dialog, not in the readout text. An inline `· derived` suffix was tried and removed as visual noise in a compact readout. Keep both of those explanations in place; do not let derivation become entirely unexplained.

## Visual direction

- Warm paper background, deep evergreen ink, coral movement accents, yellow highlights, and muted blue-green map treatment.
- The route is colored by chronology, oldest to newest, along the `ROUTE_RAMP` stops in `app.js`: indigo `#3a2a9e` → blue → cyan → green → yellow → orange → crimson `#d92d5e`. It travels roughly 547 degrees of hue. Two narrower ramps came before it — plum-to-coral, then indigo-to-orange at about 95 degrees — and both left most of a long journey looking the same colour, because a warm-only sweep has nowhere to go in the middle.
- The ramp passes through green, which is also the cache-marker colour. They stay apart because the route green is much lighter: the nearest band sits 97 units from the marker's `#1f684f` in RGB. Keep that separation if the ramp is retuned. Purple is used because every other hue is already spoken for — green is the cache-stop markers, coral is movement and the bug, yellow is the bug marker — so an on-palette green ramp would blend old route segments into the stop dots. The stops are hand-picked rather than interpolated end to end, because a single purple-to-orange interpolation passes through a muddy grey-brown at its midpoint.
- `app.js` publishes that ramp once as the `--route-ramp` custom property. The map bands and the timeline track fill both read it, so the scrubber *is* the route's legend. Do not hardcode the ramp a second time in CSS.
- Georgia is the display face; system sans-serif fonts handle interface copy.
- Use rounded, tactile controls with restrained shadows. Avoid generic blue SaaS styling.
- Zoom lives in the map topbar with the other controls, as our own buttons; Leaflet's built-in `zoomControl` is disabled. They must call `disengageFollow` like any other manual map interaction.
- The map topbar splits into two groups: zoom on the left, view controls on the right.
- Playback can be scored with Flight of the Bumblebee, chosen from a menu on the map topbar and off by default, because unannounced audio is hostile and browsers block it before a gesture anyway. Tempo follows playback speed but is capped at 2x; beyond that the piece smears.
- Six synthesised voices are offered so the timbre can be compared in place. What separates them from sounding like a synth is not the waveform: detuned pairs, a filter envelope that closes as a note decays, a shared convolution reverb, per-note dynamics with an accent every fourth note, and a little timing scatter. A single oscillator with a fixed envelope will always read as electronic no matter which waveform it uses.
- The music is **synthesised from note data, never a recording**. Rimsky-Korsakov's composition entered the public domain long ago, but every recording of it carries its own separate copyright. Synthesising sidesteps that entirely and keeps a binary out of the repo. Do not swap in an audio file without clearing its licence.
- The map topbar carries only its controls. A "Journey view" label used to sit opposite them, but there is no second kind of view for it to distinguish.
- Preserve OpenStreetMap attribution whenever its tiles are displayed.
- Respect `prefers-reduced-motion`.

## Confirmed gotchas

- Leaflet JavaScript is not enough: its base stylesheet supplies essential pane positioning. When the external stylesheet failed to load, markers rendered thousands of pixels below the map. Keep Leaflet CSS local and load it before `styles.css`.
- The vendored data files carry their own `DATA_VERSION` in `country-lookup.js`. `index.html` only cache-busts the authored CSS and JS, so regenerating `countries.json` or `us-states.json` left browsers serving the previous copy — continents silently came back empty until the version was added. Bump it whenever `tools/` regenerates a boundary file. The same trap catches fixture KML during testing.
- The in-app browser can retain a stale static stylesheet after a normal reload. The current HTML uses cache-busting query strings for authored CSS and JavaScript. Increment them when a verification reload demonstrably serves stale assets.
- At ordinary 1280×720 desktop sizing, a large minimum workspace height pushes the player below the fold. The desktop workspace currently uses `height: calc(100vh - 270px)` with a 450px minimum.
- At 390×844, the mobile map currently uses `64vh` with a 520px minimum so the player ends just above the initial viewport edge.
- Leaflet map tiles still require network access even though Leaflet itself is vendored.
- The follow camera multiplies tile consumption. A playback that pans and zooms across the world pulls far more tiles than a static view, and OpenStreetMap's public tile servers returned HTTP 429 during camera testing. OSM's tile usage policy forbids heavy use, so a production deployment needs its own tile provider or an API key rather than the public endpoint.
- Do not read tile health from the Resource Timing API. Cross-origin images without `Timing-Allow-Origin` report `encodedBodySize: 0` whatever the outcome, so healthy OSM tiles look identical to failed ones. Check `img.complete && img.naturalWidth > 0`, or fetch a tile directly, before concluding anything is broken.
- Changing zoom drops the old tile level before the new one paints, and with nothing behind it the bare container showed through as a grey flash. A second tile layer capped at `maxNativeZoom: 4` sits underneath, blurred, so the gap shows an out-of-focus map instead of flat colour. Its handful of low-zoom tiles are cached after first load. The container colour was also retuned to sit closer to how tiles look once the tile-pane filter is applied.
- A tight, held camera frame is not achievable on the large fixture, and this was measured rather than guessed. Holding only on places where the bug lingers leaves it off-screen for 30-50 seconds of playback; splitting on relocation jumps gives 58-108 camera moves; a frame wide enough to move only every couple of seconds spans about 4,000 km. The cause is that playback advances by stop index, so the bug hops Seattle to California and back within one run. Raising the playback duration helped far more than any camera tuning did.
- `map.setView` resets the entire viewport and costs roughly an order of magnitude more than the rest of a frame: measured at a realistic 1× cadence on the large fixture, per-frame work went from 0.8 ms to about 8–9 ms once the camera was moving. `updateCamera` therefore skips moves below `CAMERA_MIN_PIXEL_STEP`/`CAMERA_MIN_ZOOM_STEP` (a converged camera costs 0.23 ms) and throttles to `CAMERA_MIN_INTERVAL`. Easing is expressed against elapsed time, not frames, so the glide does not change speed with the frame rate.
- `getBoundsZoom` takes the *total* padding, so any centre shift must be exactly half the top/bottom difference. An unrelated pixel nudge pushed the bug off the top of the map.
- Leaflet marker z-index is the marker's pixel Y plus its `zIndexOffset`. Stop markers offset by `100 + index`, which on the 2,472-stop fixture reaches 2,755 and buried the bug's original offset of 1,000, so the caches drew over the bug they were being visited by. `BUG_Z_INDEX` now sits far above both terms.
- Stops the bug has not reached yet, and the dashed route preview, sit at low opacity and fade out entirely while playback runs, returning when it pauses. They stay clickable when visible so the map remains a way to jump through the journey; on a long journey showing them all at full strength made the map unreadable.
- The player's location line reads `region, country • CODE`, with the code linking to the cache. Leading with the place keeps the line steady across a run of stops in one area instead of rewriting itself at every cache.
- The places dialog reuses `.about-dialog` for its panel, so any bare element selector under that class reaches it too. A `.about-dialog ol` rule meant for the How it works steps indented the country rows and imposed a grid gap on them; those step styles now live on `.dialog-steps`. Scope by class, not by tag, in a shell two dialogs share.
- `.player-position` styles the "Stop N of M" line with a 9px block rule. Written as a descendant selector it also caught the bullet span inside the location line and stacked one line into three, so those rules must stay direct-child (`> span`).
- Animating `max-height` to a generous fixed bound looks instant: the element stops growing at its content height, so the visible part of the transition is over in the first few percent. Measure the content and set the height, then release it to `none` afterwards so later reflows are not clipped.
- A `transitionend` listener registered with `once: true` is consumed by whichever property finishes first — here the `::after` opacity beat `max-height`, so the release never ran. Filter the property and remove the listener by hand.
- CSS transitions and `requestAnimationFrame` do not advance while the preview pane is hidden, so a faded element reads back at its starting opacity even though the rule applies. Non-animatable properties in the same rule (`pointer-events`) do take effect, which is the tell. Disable the transition to verify the target value.
- The whole journey log bleeds outward by `--card-bleed` and every row pads the same amount back in, so a hovered row and the active card fill an identical box with the same corner radius. Bleeding only the active card left the hover highlight a different width, a different radius, and pushed the card's right edge inside the row's. The connector line and the cache link are both positioned against the row, so both offsets include the bleed.
- The journey log's connector line is an absolutely positioned `::before` inside each row, so nested rows must be indented with `margin-left`, never `padding-left`, or the line detaches from the markers. Depth is carried by explicit `depth-1`/`depth-2` classes rather than sibling selectors, and the connector uses `:has(+ .stop-item)` so a group's last row does not trail a line into the next place header.
- Official trackable KML is a map export, not a full activity log. Confirmed fields are document title, trackable description, official total miles, ordered cache codes, coordinates, and a route line. It omits visit dates, event type, log text, cache titles, photos, country, and region.
- The anonymously accessible trackable details page is the inverse: it provides rich history but no coordinates. Confirmed fields include date, action type, cacher, cache name/code when location-linked, displayed region, per-log URL, and public log text. It paginates at 10 records per page, newest first. Its **View Map** page and anonymous cache pages withhold coordinates until login.
- A trackable history record is not always a new position. For `TBBDVQG`, the public page has 22 records but only 6 `Dropped Off` events; the other records include retrievals, discoveries, and notes. Those 6 drop cache codes match the KML's 6 mapped stops in reverse chronological order. Model a narrative event stream separately from the position-changing route.
- The KML may have fewer mapped stops than the trackable page has history records because logs without usable coordinates are omitted.
- Duplicate cache codes are valid return visits and must retain their order. `TBA5TD9.kml` currently has 2,472 mapped stops and 2,428 unique cache codes.
- Some routes cross the antimeridian. When adjacent normalized longitudes differ by more than 180 degrees, end the departing segment at one ±180° edge and resume at the opposite edge at the same interpolated latitude; simply starting a new part drops the visible flight into and out of that region. Interpolate animation over the shorter longitude delta. Because Leaflet repeats basemap tiles but not vector layers, repeat every route part and the animated bug at longitude offsets −360°, 0°, and +360°. Stop markers instead unwrap once against the visible world copy. The large fixture crosses into Asia between stops 2,178–2,179 and back out between 2,218–2,219.
- The traveled route is drawn as up to `ROUTE_BANDS` (24) polylines, not one. Beyond enabling the chronological ramp, this fixed a real cost: `updateRoute` used to rebuild the entire traveled path every animation frame — `journey.slice(0, i + 1)`, antimeridian splitting, then three world copies, roughly 7,400 coordinate pairs per frame near the end of the large fixture. Measured over a 400-step sweep of that fixture, per-update cost fell from mean 10.3 ms / p95 24.7 ms / max 101.6 ms to mean 0.7 ms / p95 1.6 ms / max 7.9 ms, moving every frame inside the 16.7 ms budget. A frame now rewrites only the active band; all bands are re-settled solely when a band boundary is crossed or the timeline is scrubbed backwards.
- Adjacent route bands must share their boundary stop, or a visible gap opens at each colour change.
- The journey link's format version must be written with `writeVarint`, not pushed as a raw byte. The reader zigzag-decodes every integer, so a raw `1` comes back as `-1` and every link silently fails its own version check and falls back to the sample.
- Stop markers follow the viewport, not a fixed sample. Sampling the whole journey drew only every 21st stop of the large fixture — 119 of 2,472, under 5% — so the route bent through caches with nothing to click. `refreshStopMarkers` runs on `moveend` and draws the stops actually in view up to `MARKER_BUDGET`, sampling within that set only when the view holds more. Zooming in therefore reveals every stop in view.
- Markers are drawn once at the longitude of whichever world copy is on screen, unwrapped against the view centre, rather than three copies of each. The route still needs all three copies; the markers do not.
- Marker coverage and the current-stop highlight have to agree. The highlight resolves to the nearest drawn index, since the exact stop may not have a marker when the view is sampling.
- Map buttons drop their labels on mobile with `font-size: 0`, which leaves the flex `gap` behind and pushes the icon off centre by half of it. Zero the gap as well, or the icon-only button is visibly lopsided.
- `.player-card` is anchored `bottom: 10px` inside `.map-stage`, so its bottom edge does not move when the card grows. Adding rows pushes its top upward and eats into `.map-legend`, whose offset is hardcoded per breakpoint and must be re-measured.
- The journey log rebuilds from a render signature, not on every stop. The signature covers structure only — mode, which places are open, and the leaf window — while active-row highlighting stays a class toggle, so playback never re-renders the list.
- Long histories need bounded DOM and Leaflet work. The current renderer virtualizes the journey log to a 64-row window and draws only stops inside the padded viewport, capped at `MARKER_BUDGET` (260). Each drawn stop appears in the visible world copy once, while route parts and the animated bug repeat across three world copies.
- Country containment alone is not enough for geocaching coordinates. 272 of `TBA5TD9.kml`'s 2,472 stops fall outside every 50m polygon, and every one of them is a shoreline cache: 147 within 1 km of a coast, 119 within 1–5 km, 6 within 5–25 km, none mid-ocean. `country-lookup.js` therefore snaps an uncontained point to the nearest boundary within `COAST_TOLERANCE_KM` (25 km). Without it, 11% of that journey loses its country and Macao and Monaco vanish from the trip entirely.
- State boundaries come from Natural Earth's 10m admin-1 set, not 50m. Countries tolerate coarse data because they are large and mostly separated by coastline, which is why every unmatched stop was harmlessly out at sea. States share long land borders that follow rivers and roads — exactly where caches cluster — so 50m generalization would misassign stops near state lines. For the same reason `STATE_TOLERANCE_KM` is 10 km rather than the coastal 25 km: a generous snap is safe when the alternative is ocean and wrong when a neighbouring state is nearby.
- State lookup is gated on the stop's country already being the United States. Without that gate, `us-states.json` containing only US polygons would happily snap a Canadian stop to the nearest US state.
- Scanning all 1,620 country polygons per stop cost about 1.4 seconds for the large fixture. A 10-degree grid index cut it to roughly 450 ms. A finer 5-degree grid changed nothing, because the remaining cost is walking the segments of large rings, not choosing candidate polygons.
- Enrichment yields between time slices so playback never drops a frame, but only while `document.hidden` is false. A hidden tab clamps timers to about one second, which turned the same 450 ms pass into more than a minute during testing.

## Next engineering milestone

Enrich imported journeys without weakening the KML-first privacy and data-integrity rules. Keep acquisition separate from presentation so KML/GPX, an approved API, and fixtures all produce the same internal stop shape.

Implementation order:

1. Keep the browser smoke suite current as importer, boundary, and share formats change; add full renderer regression coverage when the runner begins inspecting the application DOM.
2. Decide whether a GPX export contributes history data that KML lacks before adding it.
3. Ask Geocaching HQ for Authorized Developer access or express written permission for the proposed public-trackable-history use, and confirm the approved methods and fields.
4. Design the OAuth-backed direct-import adapter; do not scrape signed-in pages as the product data layer.
5. A shareable link now exists without storage: `journey-link.js` puts the journey in the URL fragment, so there is nothing to store, consent to, or delete. A *saved* journey format, which does store data server-side, still requires storage, consent, and deletion behavior to be defined first.

Expected normalized stop fields include:

- stable log or stop identifier
- event date and type
- public cache code and display name
- latitude and longitude
- region and country
- movement distance and cumulative distance
- public log URL
- optional story text and photo references

Before implementation, decide how to handle visits versus drops/retrievals, duplicate logs, missing coordinates, impossible jumps, archived caches, and active-cache location privacy.
